# Seedmux 独立审查

先加载应用提供的 `seedmux-team` skill，按其派发和验收规则执行。全部审查者都是 Seedmux 的真实 pane；禁止创建进程内 Pi 子会话、私有 Worker 池或自动修复循环。

主控确定目标仓库、当前改动、审查范围和验收条件。给审查者明确只读范围、基线/目标 commit 或工作区快照、相关需求与执行过的检查；不要把作者结论当成事实。共享 checkout 若还在变动，先明确所审版本，结果不能自动适用于之后的改动。

审查者独立检查实际代码与行为，寻找可复现的正确性、数据损坏、兼容性或用户可见问题；禁止改文件、提交或推送。必要的测试只能在授权范围内运行。不因个人风格偏好或猜测阻塞。

回执给出以下之一：

- PASS：未发现阻塞问题，并列出审查范围、验证证据和未覆盖部分。
- FAIL：逐项说明严重度、触发条件、实际与预期行为、文件位置或命令证据、如何验证修复。
- BLOCKED：缺少什么证据或环境，不能据此声称通过。

主控读取真实回执并核对证据。确认的问题交给原执行者修复；修复后明确增量范围，再按需续派审查。低风险建议单列，不能把一轮命令成功视为需求已满足，也不能因为多轮未通过而降低标准。存在分歧时回到需求与复现证据，需要裁决再引入独立 pane，不设置隐藏仲裁器。

结果和未解决问题回到当前会话与项目指定 tracker。涉及白板决策时按 `project-flow` 回写 Agora；不要为审查另建任务数据库。
